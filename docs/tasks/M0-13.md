- **Käivitus:** `push` kõigil harudel, `pull_request`, ja `push` siltidele `v*`. Töö jookseb `windows-latest`. `concurrency` tühistab sama haru vana jooksu. `permissions: contents: read`; ainult Release'i samm saab `contents: write`.
- **Töö 1 `checks` (alati):**
  1. `actions/checkout`, `actions/setup-node` (Node **26.13.0**, `cache: pnpm` kui toimib).
  2. Node 26 ei tarni Corepacki kaasa: `npm install -g corepack@0.36.0`, siis `corepack enable`. Kontrolli, et `pnpm --version` on **12.18.0** (väljastatakse logisse).
  3. `pnpm install --frozen-lockfile`.
  4. `pnpm check`, `pnpm format:check`.
  5. `pnpm exec playwright install chromium`, siis `pnpm e2e` (`CI=true`, nii et `reuseExistingServer` on välja lülitatud). Playwrighti `test-results/` laaditakse artefaktiks ainult ebaõnnestumisel.
  6. Rust kaustas `apps/desktop/src-tauri`: `cargo fmt --check`, `cargo test --locked`, `cargo clippy --locked --features desktop -- -D warnings`. Rusti vahemälu ainult `actions/cache` kaudu (võti `Cargo.lock` räsi), mitte kolmanda poole tegevusega.
- **Töö 2 `installer` (`needs: checks`, ainult `main`-i push või `v*` silt):** sama keskkond, siis `pnpm tauri build`. Artefakt `pcbk-msi` on `src-tauri/target/release/bundle/msi/*.msi`.
- **Silt `v*`:** eraldi samm `gh release create "$GITHUB_REF_NAME" <msi> --generate-notes` (`gh` on runneril olemas, kasuta `GITHUB_TOKEN`-it; kolmanda poole release-tegevust ei lisa). Ainult selles sammus `permissions: contents: write`.
- **Tegevuste versioonid:** iga `uses:` on lukustatud täpse versiooni või commit-räsiga; kontrolli enne kasutamist ametlikust dokumentatsioonist/GitHubi lehelt, ära arva. Kolmanda poole tegevusi ei kasutata.
- **`tauri.conf.json`:**
  - `bundle.active: true`, `bundle.targets: ["msi"]`, `bundle.icon: ["icons/icon.ico"]`.
  - `bundle.windows.webviewInstallMode: { "type": "offlineInstaller" }` (WebView2 võrguühenduseta paigaldaja).
  - `bundle.windows.wix.language: "et-EE"`, kui WiX seda toetab; muidu `en-US` ja märgi üleandmisse.
  - `version`: `0.1.0`. MSI nõuab numbrilist versiooni; kui `0.0.0` toimib, ära muuda, kui mitte, kasuta `0.1.0` ja kirjuta põhjus üleandmisse. Silt `v*` peab ühtima selle versiooniga (CI kontrollib, et `GITHUB_REF_NAME == v<version>`, muidu kukub).
  - `fileAssociations` jääb nagu on; `.msi` registreerib selle paigaldamisel.
  - CSP ja capabilities jäävad muutmata.
- **Ei lisata:** koodiallkirjastamine (v1 enne avaldamist, eraldi otsus), automaatne uuendaja, macOS/Linux ehitus.

## Lisaparandus pärast esimest CI jooksu (2026-11-09)
`checks` kukkus sammus „Enable Corepack and verify pnpm“: `npm install -g corepack@0.36.0` → `EEXIST: file already exists` failil `yarn` runneri npm-prefiksis. Runneri npm-prefiksis on juba `yarn`-i käivitusfail, mida Corepack tahab ise paigaldada. Parandus: lisa **mõlemas töös** (`checks`, `installer`) käsule `--force` (`npm.cmd install -g corepack@0.36.0 --force`), mis kirjutab üle ainult need käivitusfailid npm-i globaalses prefiksis. Pnpm-versiooni kontroll (12.18.0) jääb. Ära eemalda Corepacki ega muuda kontrolle. Test: pushi pärast kasutaja luba ja esita järgmise jooksu kukkunud sammu või rohelise tulemuse väljund. Commit `ci: overwrite preinstalled yarn shim when installing corepack`.

## Lisaparandus 2 pärast teist CI jooksu (2026-11-09)
Corepack ja paigaldus läbisid; `pnpm check` kukkus kolme töökõlbliku testi ajalimiidi (5000 ms) tõttu GitHubi aeglasemal runneril: `tooling/backend-typecheck.test.ts › root typecheck rejects browser and Node globals in every backend layer` ning `tooling/api-digest.test.ts › digest lists exported function signatures without bodies` ja `› digest is sorted and stable across runs`. Need käivitavad `tsc`/`node` alamprotsesse. Teised sama faili testid kasutavad juba selgeid ajalimiite (15 s, 30 s).
**Parandus:** anna neile kolmele testile selge ajalimiit nagu naabritel (`60_000` ms). Sisu, väiteid ega globaalset `testTimeout`-it ei muudeta, teisi teste ei puututa. Kohalik kontroll: `pnpm test tooling` ja `pnpm check`. Commit `ci: give process-spawning tooling tests explicit timeouts`. Ära pushi enne kasutaja luba.

## Lisaparandus 3 pärast kolmandat CI jooksu (2026-11-09)
`pnpm check`, vormindus ja e2e läbisid GitHubis. `cargo test` kukkus ühe testiga: `tests/storage.rs › opened_path_has_no_verbatim_prefix`. Runneri ajutine kaust on lühinimega (`C:\Users\RUNNER~1\…`), mootor tagastab `dunce::canonicalize` kaudu pika nime (`C:\Users\runneradmin\…`). Toote käitumine (kanooniline tee ilma `\?\` prefiksita) on õige; test võrdles tagastatud teed sisendiga sõna-sõnalt.
**Parandus (ainult test):** arvuta oodatav tee pärast faili loomist `dunce::canonicalize(&path)` kaudu ja võrdle seda `created.path` ja `reopened.path` vastu. Kettatähe-prefiksi kontroll (`Prefix::Disk`) jääb muutmata; `\?\` ei tohi tulemuses olla. Toote koodi ei muudeta. Kohalik kontroll: `cargo test --locked` ja `cargo clippy --locked --features desktop -- -D warnings`. Commit `test: compare canonical path in verbatim-prefix test`. Ära pushi enne kasutaja luba.
