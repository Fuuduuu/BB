# M1-2-2 · Foto import (Rust ja veeb) ning `pcbk://photo`

## Eesmärk
Foto saab projekti faili tervikliku impordina (originaal muutmata, suurel fotol ≤ 12 MP kuvamisvariant, EXIF-suund `transform`-iks) ja seda saab kuvada aadressilt, mis teenindab ainult avatud seansi fotosid. Sama töötab veebis IndexedDB-ga. Dokumendikäsk `photo.add` ja lõuendi kiht tulevad kaartides M1-2-3 ja M1-2-4; see kaart annab `PhotoRef`-i ja URL-i.

## Otsused ja liidesed
- **Sõltuvused (kasutaja kinnitas O1):** `image` (ainult `jpeg` ja `png` funktsioonid, `default-features = false`) ja `kamadak-exif`, täpsed versioonid `=x.y.z` nagu teistel. Lisamine vajab võrku; kui see ebaõnnestub, peatu ja kirjuta arhitektile.
- **`PhotoStore` port:** `importPath(session, path, id): Promise<PhotoRef>` (ainult töölaud), `importBytes(session, bytes: ArrayBuffer, id, name): Promise<PhotoRef>`, `prune(session, keep: string[]): Promise<void>`, `url(session, id, variant: 'display' | 'original'): string`. `id` annab kutsuja (`ids.newId('pho')`). `name` = failinimi ilma laiendita; kleepimisel „Kleebitud foto“.
- **Import (Rust, `storage/photos.rs`):** loe baidid → tuvasta formaat (JPEG/PNG; muu, sh HEIC → `unsupported_image`) → loe mõõdud ilma täisdekodeerimiseta → kui > 100 MP või fail > 200 MB → `image_too_large` → EXIF orientatsioon → kui > 12 MP, dekodeeri ja vähenda proportsionaalselt ≤ 12 MP-ni (`Triangle` filter), salvesta JPEG kvaliteediga 90 → **üks tehing**: `photos` read `original` (algsed baidid muutmata) ja vajadusel `display`. Tagasta `PhotoRef { id, side: 'top', name, widthPx, heightPx (originaali salvestatud mõõdud), transform }`. Vigane või katkine fail → `corrupt_image`; tehingut ei alustata.
- **EXIF → `transform`** (vastab lõuendi `stage.ts` maatriksitele): 1 `none`, 2 `mirror`, 3 `rot180`, 4 `mirror_rot180`, 5 `mirror_rot270`, 6 `rot90`, 7 `mirror_rot90`, 8 `rot270`; puuduv või vigane → `none`.
- **Uued veapõhjused** (`Reason` ja `StorageReason`): `unsupported_image` („Seda pildivormingut ei saa avada. Kasuta JPEG- või PNG-faili.“), `image_too_large` („Pilt on liiga suur (üle 100 MP või 200 MB).“), `corrupt_image` („Pildifail on vigane või poolik.“).
- **Protokoll:** `register_asynchronous_uri_scheme_protocol("pcbk", …)`. Tee `/photo/<session>/<photoId>?v=display|original`; `display` puudumisel antakse originaal. Teenindatakse ainult **aktiivse** seansi fotosid; muu seanss, tundmatu id või vigane tee → 404. Vastus: õige `Content-Type`, `Cache-Control: no-store`. URL-i ehitab `photos-tauri.ts`: Windowsis `http://pcbk.localhost/photo/…`, mujal `pcbk://localhost/photo/…`. CSP `img-src`-sse lisandub `pcbk: http://pcbk.localhost`.
- **Koristus avamisel:** `ProjectService` kutsub pärast kirjutatavat avamist `photos.prune(session, doc.photos.map(p => p.id))`; Rust kustutab ülejäänud `photos` read ühe tehinguna. Kirjutuskaitstud avamisel ei kutsuta. Domeeniloogikat (dokumendi lugemist) Rustis pole.
- **`project_open` `photos_meta`** jääb ära (03 §9 parandatakse): protokoll valib variandi ise.
- **Veeb:** IndexedDB uus objektihoidla `photos` (andmebaasi versioon +1, olemasolevad kirjed säilivad), võti `<projectId>/<photoId>/<variant>`, väärtus `{ mime, width, height, bytes: Blob }`. `exif.ts`: JPEG APP1 orientatsiooni lugeja (ainult TIFF päis ja tag 0x0112, mõlemad baidijärjestused). Suur pilt vähendatakse `createImageBitmap(blob, { imageOrientation: 'none' })` + `OffscreenCanvas` kaudu (kui brauser ei toeta, salvesta ainult originaal). `url` tagastab vahemälus `URL.createObjectURL`-i; projekti sulgemisel `revokeObjectURL`. Veebi koopiat endiselt pole.
