## Otsused ja liidesed
- **Moodul:** `photoEngine: EngineModule = { id: 'photo', owns: ['photos', 'activePhotoId', 'scale'], commands }`. Moodulil ei ole `dependsOn` ega `derive`. Käsu `title` on käsu id, nagu teistel moodulitel.
- **`photo.add { photo: PhotoRef }`** (`PhotoRefSchema`):
  - M1.2-s on plaadil üks foto. Kui `photos` pole tühi → `reject('photo_limit')`. Foto vahetus ja teine foto tulevad M1.3-s.
  - `side` peab olema `'top'`, muidu `reject('photo_side_unsupported')`. `toBoard` peab puuduma, muidu `reject('photo_alignment_unsupported')`.
  - Lisab foto ja seab `activePhotoId = photo.id`. Mõlemad muutused on üks samm; tagasivõtmine eemaldab mõlemad.
- **`photo.setTransform { id, transform }`:** foto puudub → `reject('photo_missing')`. Sama `transform` → käsk ei muuda midagi, `rev` ei tõuse ja ajalukku kirjet ei tule (nagu tühi `project.setInfo`).
- **`photo.setScale { a: Vec2, b: Vec2, mm: number }`:** mootor arvutab `pxPerMm = |b − a| / mm`, et mõõtkava ja kalibreerimispunktid ei saaks lahku minna. Plaanis oli `{ pxPerMm, calib }`, see on täpsustatud.
  - Valideerimine: `mm` lõplik, `0 < mm ≤ 1000`; `a` ja `b` lõplikud.
  - Kui `|b − a| < 5` px → `reject('calibration_too_short')`. Kui tulemus on väljaspool `[0.1, 1000]` → `reject('calibration_out_of_range')`.
  - Tulemus: `scale = { pxPerMm, calibrated: true, calib: { a, b, mm } }`, üks samm. Komponentide `at` ei muutu.
  - Fotot see käsk ei nõua (kalibreerida saab ka fotota plaadil).
- **Tööpind:** `boardSurface(doc: Pick<BoardDoc, 'photos' | 'activePhotoId'>): { width: number; height: number }` failis `domain/src/geometry/surface.ts`. Aktiivse foto korral `{ width: widthPx, height: heightPx }` (originaali mõõdud; teisendus pöörab ainult vaadet). Fotota või kui `activePhotoId` ei viita ühelegi fotole → `{ width: 2000, height: 1400 }`. Asukoht on `geometry`, sest UI tohib sealt käituskoodi võtta.
- **Arhitekti vastus ehitajale (2026-11-12): sisend on kirjutuskaitstud ja minimaalne.** Signatuur on `boardSurface(doc: { readonly photos: readonly { readonly id: string; readonly widthPx: number; readonly heightPx: number }[]; readonly activePhotoId?: string | undefined }): { width: number; height: number }`. Nii saab `Workbench` anda `snapshot.doc` otse ja mootor/testid tavalise `BoardDoc`-i. Tüübi võib nimetada (nt `SurfaceSource`) ja eksportida koos funktsiooniga. Käitumine on sama.
- **Veakoodide tekstid:** `reject` põhjustel pole praegu tõlkekohta, seega selles kaardis tekste ei lisata. Kasutajaliides (M1-2-5 ja M1-2-6) kasutab neid:
  - `photo_limit`: „Plaadil on juba foto. Foto vahetus tuleb hiljem.“
  - `photo_missing`: „Fotot ei leitud.“
  - `photo_side_unsupported` ja `photo_alignment_unsupported`: „Seda fotot ei saa veel lisada.“
  - `calibration_too_short`: „Punktid on liiga lähestikku. Vali kaugemal olevad punktid.“
  - `calibration_out_of_range`: „Mõõtkava tuli ebausutav. Kontrolli punkte ja millimeetreid.“
- **M1-2-2 märkus 1 (Rust):** `import_photo_bytes` ei hoia `sessions` lukku dekodeerimise ajal. Käik: lukk → seanss olemas ja `writable()` → lukk vabaks → `prepare(bytes)` → lukk uuesti → seanss olemas ja kirjutatav → tehing. Kui seanss vahepeal sulgus, on tulemus `Reason::Unknown` nagu praegu tundmatu seansi korral. Olemasolevad testid jäävad muutmata ja roheliseks; uut testi ei nõuta.
